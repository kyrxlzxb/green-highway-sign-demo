# リポジトリの文書・コメント作成ルール

[日本語](PERSONAL_REPOSITORY_RULES.ja.md) | [English](PERSONAL_REPOSITORY_RULES.md)

## 英語と日本語

- プロジェクト文書は英語で作成し、意味と内容が同等の完全な日本語版を用意する。日本語版を要約にしない。手順、例、要件、制約、検証状況を一致させる。
- 両言語を同じ変更で更新する。完了と報告する前に、内容の同等性と相対リンクを確認する。
- 英語の原文は README.en.md、完全な日本語のトップページは README.md とする。その他の文書は <name>.md と <name>.ja.md の組にする。簡潔な `日本語 | English` リンクを設け、翻訳に関する前置きは追加しない。
- ツールが要求するファイル名とスキーマを維持する。AGENTS.md は英語とし、日本語の参照版を docs/AGENTS.ja.md に置く。ツールが多言語の成果物を明示的にサポートしていない限り、ツール管理文書の日本語版は自動検出の対象外に置く。
- プロジェクトで管理する実質的な説明コメントと docstring は、EN/JA の説明を隣接させて併記する。実行可能なソースを複製せず、自明なコードに不要なコメントを追加しない。
- 識別子、コマンド、パス、API フィールド、設定キー、実行時プロンプトの言語、アプリケーションデータ、法的表示、第三者のコード、機械処理用のディレクティブは維持する。文書の翻訳によって動作を変更しない。

## 成果物の内容

- ユーザーの指示は作業に反映し、成果物の中でその指示を転載したり説明したりしない。
- 会話中の説明、個人的な背景、例示的な発言、作業を依頼した理由を、README、その他の文書、コードコメント、リリースノートに転記しない。
- 日本語文書を「日本人の同僚のために」作成した、「ユーザーの依頼により」選択した、といった作成経緯の説明を書かない。
- プロジェクトに関する事実、利用手順、入出力などの契約、制約、運用や保守の理解に役立つ技術的な理由を記載する。
- 実行可能な作成・保守方針は、エージェント向けまたはコントリビューター向けのガイドに記載する。各文書の前置きとして繰り返さない。
- 提出前に両言語を確認し、会話内容の混入、指示に関する不要な説明、根拠のない事実の記述を取り除く。

## 不確かな事実

- 事実を記載する前に、利用可能な根拠を確認する。必要な事実が依然として不明な場合は、該当箇所を確定したり、その事実に依存する作業を行ったりする前に、依頼者に確認する。
- ファイルの場所、使用中のバージョン、サーバーのディレクトリ構成、モデルの成果物、デプロイ用コマンドも対象とする。もっともらしい値を作らず、過去の会話を現在のデプロイ状態の証拠として扱わない。
- 未解決事項を作業メモに明記し、確認を待つ。無関係な作業は続行する。必要な事実が未確認の間は、該当作業を完了と報告しない。
